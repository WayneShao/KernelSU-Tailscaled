# 2.0.0-beta.5 Verification

## Device Package

Both the OnePlus PKX110 and Xiaomi nezha received the same ARM64 ZIP through
`ksud module install`. The installer activated the runtime and published its
KernelSU WebUI and Action files. No post-install module-file patches or device
reboots were used for this candidate.

ARM64 ZIP SHA-256:
`6d851adee28c140d853cc69a31fa5e51659d1ebccd914f666784acc2ab25d043`.

Both devices reported module version `2.0.0-beta.5`, backend `Running`, and all
four component fields `running` after installation. Existing node identities,
addresses, and names were preserved. Their pre-existing DNS acceptance preferences
remain enabled, with upstream `/etc/resolv.conf` warnings reported honestly.

## Defects Found Before This Candidate

- Android mksh required explicit descriptor inheritance for lock handoffs.
- BusyBox AWK needed a portable JSON scalar delimiter test.
- Android's default mv did not replace directory symlinks with the expected `-T`
  semantics; pointer replacement uses the KernelSU BusyBox implementation.
- A supervisor's blocked control subshell could outlive its terminated parent,
  acquire the lock after an upgrade, and act on the new runtime. A host regression
  reproduced socket deletion. Reconciliation now verifies the current registered
  supervisor identity after acquiring the lock and exits if superseded.
- Failed process identity checks previously discarded live ownership records.
  Ambiguous records now block replacement and retain the socket for diagnosis.

An earlier Xiaomi beta encountered live processes with deleted runtime records.
Those exact processes were identified and stopped before this complete candidate
was installed. This was one-time cleanup of unpublished development builds,
not a required post-install repair step for the distributable ZIP.

## Scope And Limits

Targeted ownership and orphan-supervisor regressions failed before the fixes and
passed afterward, including an mksh lock regression. ZIP validation passed before
the two installations. CI is the record for the complete final source suite,
frontend build, browser checks, and reproducible release packages.

Automated browser checks and installed asset checks are distinct from physically
viewing the final KernelSU Details page. The device was locked during attempted
visual inspection; this record does not claim final on-device visual sign-off.
ARM execution, broad Android/Magisk/APatch compatibility, userspace networking,
and multi-day stability are not established. This remains a prerelease.
