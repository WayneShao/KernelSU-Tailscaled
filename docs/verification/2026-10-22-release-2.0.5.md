# v2.0.5 release validation (2026-10-22)

## Authorization

The maintainer explicitly authorized a formal release after the requested real
Xiaomi old-engine-to-new-engine test passes, followed by an Issue #1 mention.
This supersedes earlier candidate acceptance notes. No public beta is used.

## Xiaomi real upgrade

Temporarily selected a clone of the tested dev.2 runtime with preserved v2.0.4
engine binaries (1.102.3) and a recomputed bundle manifest. The normal generation
was untouched. Identity and configuration were backed up before switching.
Observed the actual daemon running 1.102.3, then invoked engine-check,
engine-prepare and engine-apply, the same controller actions used by WebUI.
The official 1.104.2 ARM64 download passed checksum/version checks. The running
/proc/<daemon>/exe changed to the separately downloaded engine. Identity/config
matched backups; backend and all components returned to Running; direct public
peer ping succeeded (24 ms). Restored the normal module runtime afterward.

## Final ZIP on both devices

Installed the complete ARM64 v2.0.5 ZIP through normal `ksud module install` on
verified OnePlus PKX110 and Xiaomi nezha. No post-install script patching.

- Module/runtime 2.0.5; selected engine 1.104.2 on both.
- Identity/configuration SHA-256 checks passed before/after installation.
- Supervisor, daemon, data plane and WebUI running; backend Running; Health empty.
- Separately updated engine retained across module installation.
- Direct public peer ping: Xiaomi 16 ms, OnePlus 20 ms. Local WebUI HTTP 200 both.
- Earlier dev.2 with this implementation passed an authorized OnePlus reboot:
  automatic activation, external engine retained. Mountify removal completed by
  that reboot; ordinary KSU installation then succeeded.

## Limits

Phone controller actions were tested over ADB; manual KernelSU WebView taps were
not separately witnessed. Browser tests use a mock KSU bridge. Isolated fresh
login returned an auth URL without a proxy but did not complete new-account
browser authorization. The reporter ROM and ARM32 hardware remain unverified.
Final 2.0.5 was hot-installed; prior dev.2 reboot evidence is not a claim that
final 2.0.5 itself was reboot-tested. These tests establish the observed cases.
