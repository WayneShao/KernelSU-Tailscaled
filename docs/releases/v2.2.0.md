# KernelSU-Tailscaled v2.2.0 — automatic Taildrop delivery

Received files now land automatically in **`/sdcard/Download`**, or a folder
selected under **WebUI → Taildrop → Destination folder → Save folder**.
English remains the default; Simplified Chinese and Headscale sign-in remain
available. The official Tailscale engine remains **1.104.2**.

## Install

- **Universal:** `KernelSU-Tailscaled-v2.2.0.zip` includes ARM and ARM64.
- **ARM64 only:** `KernelSU-Tailscaled-arm64-v2.2.0.zip`.
- **32-bit ARM:** `KernelSU-Tailscaled-arm-v2.2.0.zip`.

Install over the existing `kernelsu-tailscaled` module in KernelSU Manager.
Do not uninstall or delete `/data/adb/kernelsu-tailscaled` first. Login,
preferences, queued files and the saved destination are retained. Reopen the
WebUI after installation. No Android reboot or new sign-in is requested.
Version code **20000023** upgrades both 2.1.2 and the private 2.2.0-dev.1 candidate.

## Receiving behavior

- One supervised official `tailscale file get --loop --conflict=rename` process
  waits for arrival notifications. No periodic retrieval command or inbox scan
  is added. The existing supervisor checks process health and recovers crashes.
- Missing destination folders are created below mounted Android shared storage.
  Unicode, spaces and apostrophes are supported. Private paths, mount roots,
  traversal, control characters and symlink destination components are refused.
- Saving a folder restarts only the receiver, not the daemon or connection.
  The selection survives module restarts and upgrades. Old configurations
  without a destination key use `/sdcard/Download` automatically.
- Existing files are never overwritten. Duplicate names receive numbered suffixes.
- If the destination is unavailable, files remain in the private inbox until
  recovery. Check **Logs** and **Diagnostic records**. Receiver **Running** means
  the owned process is live, not that every copy has succeeded. An interrupted
  or full-disk copy can leave a partial destination file; the inbox original is
  retained until the official CLI completes the copy successfully.
- Do not run a second receiving CLI against the same inbox. Headscale must
  advertise file sharing, as with earlier releases.

The feature is kept separately on **feature/taildrop-auto-save** and integrated
into **all-features-merged** for this release. Upstream authorship and BSD-3-Clause
licensing are retained; this is not an official Tailscale or KernelSU release.

## Verification

On a rooted OnePlus 9 Pro with **SELinux enforcing**, the candidate was exercised
with real Taildrop transfers using the existing Headscale login:

- Two previously queued archives (81,885,433 and 266,684,108 bytes) appeared in
  Downloads after installation.
- New default-folder and custom-folder transfers matched source SHA-256 hashes;
  the custom folder was saved through the actual WebUI using spaces, Unicode and
  an apostrophe. A 4 MiB binary transfer was included.
- Duplicate delivery preserved the original and produced a numbered copy, both
  with matching hashes.
- Module restart retained the selected folder and accepted another transfer.
- Making the destination unavailable kept a new file queued; restoring the
  folder delivered it automatically with a matching hash.
- Killing the receiver caused supervised recovery without restarting the daemon.
- Login-state bytes, node identity, IP addresses and exact Tailscale preferences
  were retained. Existing upstream DNS warnings were unchanged.
- Mounted-storage smoke checks accepted quoted/Unicode folders and rejected
  symlinks and traversal. Android rejected private, traversal and absent-volume
  destinations without changing the saved configuration.
- The final universal v2.2.0 ZIP was then installed through `ksud module install`.
  The custom folder survived the upgrade, and fresh transfers to both the saved
  folder and restored default Downloads matched SHA-256. No reboot was needed.

A 60.16-second idle observation measured **0.00 CPU-seconds** in the receiver,
**0.03 CPU-seconds** in the supervisor itself and **1.33 CPU-seconds** in its
reaped child processes. This short observation is not a screen-off or
battery-life guarantee.

Local gates: **155 Linux tests**, **81 frontend tests**, **18 browser scenarios**,
frontend type checking/build, ShellCheck, zero known npm audit vulnerabilities,
and package validation for all three architectures. GitHub Actions repeats the
release gates before publication and verifies reproducible ZIP bytes, release
immutability and asset attestations.

Equivalent on-device coverage for 32-bit ARM, full-disk copies, locked-user
storage, every removable-volume layout, long-term battery behavior and broad
Magisk/APatch compatibility is not established.
