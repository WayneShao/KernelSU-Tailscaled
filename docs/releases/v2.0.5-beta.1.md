# KernelSU-Tailscaled v2.0.5-beta.1

This prerelease addresses Issue #1, where a fresh standalone Android install
could fail before authentication for two independent reasons.

## Changes

- Bundles the official Tailscale 1.104.2 ARM and ARM64 static binaries. This is
  the first stable line used by this module that contains Tailscale's standalone
  Android DNS and network-monitor integration.
- Reports `android-resolver-unavailable` when the owned daemon log shows the
  observed `[::1]:53` resolver failure during login.
- Reports `android-marked-route-unreachable` when a bounded, read-only
  `ip route get 1.1.1.1 mark 0x80000` probe fails during login.
- Recommends the existing explicit userspace mode when marked native traffic is
  not routable. It never writes a persistent default route automatically.

## Binary provenance

  `b694ff9c67235da98798b9592a0cc900bc9d1613041f77722ec9bf4ce2d215cf`
- `tailscale_1.104.2_arm64.tgz`:
  `5776aaa901b5ef1916e66be5bb54b9f481cd399c9c28db123a8cab620efa237b`

Both hashes matched the corresponding `.sha256` files served over HTTPS by
`pkgs.tailscale.com`. The extracted binaries were checked for the expected ELF
architectures, embedded `1.104.2` version, and `/dev/socket/dnsproxyd` support.

## Candidate boundary

The stable KernelSU update feed remains on v2.0.4 until native-mode login and
normal runtime health have been verified on maintainer devices and the affected
ROM has had an opportunity to test the marked-route behavior.
